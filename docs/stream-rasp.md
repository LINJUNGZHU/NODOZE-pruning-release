# Stream-RASP 工程原型

后续已加入可选 `--history` 分片历史检索，见 [历史回查实验](history-recall.md)。下文记录最初仅窗口版本的边界，可靠续读仍未实现。

## 采用哪篇算法，修改了什么

基础是 [Approximate Personalized PageRank on Dynamic Graphs (KDD 2016)](https://arxiv.org/abs/1603.07796)
的维护估计/残差不变量、图变化后局部修复思想。本实现维护
`r = alpha*s + (1-alpha)*P^T*p - p`，修改一行转移概率时将
`(1-alpha)*p[u]*(P_new[u,:]-P_old[u,:])` 加到残差；再推送有符号残差。
支持加权无向通道、删除、权重更新、混合 POI 种子变化。重复事件不会重复增加通道权重。
悬空节点用自环，与旧 RASP 的返回种子处理不同。

由随机转移矩阵的 L1 非扩张性质可得 `||p-p_exact||_1 <= ||r||_1/alpha`。
输出这个后验界及收敛标志，而不是把固定迭代次数视作收敛。
这不是论文原算法的逐行复现，也不宣称继承其均摊时间定理。
节点残差扫描、邻接行更新和窗口选边仍有非局部成本。

组合已有 RASP 的严格时序共同原因分叉保护：传播近似只用于打分，选中锚点必须连同所选因果连接组计入预算。
对 [Sieve-Streaming++ (ICML 2019)](https://proceedings.mlr.press/v97/kazemi19a.html)
进行了适用性核对：我们的扩散分数会随图更新，连接组成本也变化，不满足直接使用固定单调子模目标保证的条件，因此没有强行套用它。

## 当前实现

`python -m scripts.run_stream_rasp` 逐行读取原始 CDM JSONL/GZ 或规范化事件 JSONL；不需要预置数据库。
节点声明更新类型；事件到达时先按已见节点类型—关系—节点类型频次评分，再更新统计。
因此稀有度不使用未来频次，但它是到达序列条件频次，乱序时不是严格事件时间频次。
默认每 5000 条产生一次快照，活动事件上限 20000，微批更新动态图 PPR，再对窗口重算时序连接和选边。
背景参考改为加权度分布，多 POI 使用混合种子；这两点与批量 RASP 不同，结果不能假定相等。
窗口通道重新汇总和选边仍扫描窗口，并非整个管线均为 O(新增边)。

每个快照有逐边 rarity/score/retained 和状态，进度追加到 progress.jsonl。
缺少 POI、传播未收敛或 POI 本身超预算时 retained 为 null（待决），不执行删除。
原始日志始终不改动，因此这是可重新生成的调查视图，不是物理存储压缩。
当前只有窗口内事件 ID 去重；历史节点字典、类型、频次与 PPR 状态尚未回收，整体内存不是严格有界。
离开窗口再重放的相同事件会重新计数。尚不支持崩溃恢复、持久偏移、tail 追踪、轮转和动态告警接口。
输入损坏时直接报错，不静默跳过；时间相同的事件仍不互相形成严格因果依赖。

## 后台运行

```bash
cd /root/NODOZE-pruning-release
run_id=$(date '+%Y-%m-%d_%H-%M-%S')
setsid -f python -u -m scripts.run_stream_rasp \
  --input /root/kairos-main/logs/ta1-cadets-e3-official-1-0.json \
  --poi configs/stream_cadets13_pois.json \
  --batch 5000 --window 20000 \
  --output "output/tc/stream-${run_id}" \
  > "logs/stream-${run_id}.log" 2>&1 < /dev/null
```

此 POI 文件是既有 CADETS-13 报告辅助 POI，不保证出现在示例输入分片；可替换为对应告警事件 ID 的 JSON 列表。命令读到 EOF 退出，不持续追踪追加。
本轮日志：`logs/stream-cadets13-chronological-2026-09-10_18-12-00.log` 和 `logs/stream-raw-smoke-2026-09-10_18-13-00.log`。
