# NODOZE 频率—扩散证据保全：算法与实验过程

本文记录**实际运行的 `budget-evidence-v7-r2` 第一阶段**。对应决策源码提交为 `4432328`，实验产物位于 `docs/budget-evidence-v7-r2/` 和外部 `output/tc/budget-evidence-v7-r2/`。它是一轮已用开发案例的研究实验，不是 SPARSE 作者系统的复现，也不是自动检测器评测。

## 1. 任务与数据契约

给定冻结的事件账本 $E$、报告派生的 POI 事件集合 $M$ 和原始账本事件预算 $B$，算法返回事件 ID 集合 $S$、显式调查锚点 $A$ 和各锚点选用的时间证书，满足

$$
M\subseteq S\subseteq E,\qquad |S|\leq B,\qquad
S=M\cup\bigcup_{w\in W_{\rm chosen}}\mathrm{events}(w).
$$

预算单位是**唯一账本事件 ID**。两条证据共享同一 ID 时只付一次成本；不同 ID 的平行日志分别付费。`LINEAGE:` 合成事件也占账本预算，并在结果中与原始 CDM 事件分开计数。节点用 `(host, UUID)` 区分，不能跨主机串接相同 UUID。时间证书表示实现规则下的可达性，不能直接解释为真实攻击因果。

五个输入案例是 Five Dir Case 1、Five Dir Case 3、Theia Case 1、Theia Case 3、Theia Case 5。最后一个案例曾在项目讨论中称为 `TRACE5*`；目前没有完成与论文不同命名工件的逐事件身份核验。五案都已用于研发，只属于**开发集**。POI 来自官方报告的 oracle 派生清单，本轮没有调用外部告警，也不把 POI 的效果说成自动检测效果。历史频率使用已有缓存；历史未保证全为良性，历史元数据的严格在线时间安全性标为 `unverified`。

人工参照 $L$ 是本地工件实体对展开或标注得到的**部分正例**。运行器完全不读取 $L$；只有决策与证书落盘后的独立评测、诊断进程读取它。未标注事件不等于确认误报。

```mermaid
flowchart LR
  E[冻结账本、历史缓存、报告 POI] --> A[输入与哈希审计]
  A --> F[频率统计＋背景对比扩散＋时间校准]
  F --> R[事件或计算组多视图排序]
  R --> W[合法时间证书与物化上限]
  W --> O[原始事件并集预算选择]
  O --> P[先保存选择、证书、哈希]
  P --> V[独立读取部分正例评测]
  V --> D[损失阶段与有限池标签 oracle]
```

## 2. 实际实现的算法

### 2.1 频率与扩散主评分

主分数沿用本项目已有的 `history_channel` 实现，而不是替换为 GNN。历史条件频率先按主机、关系和端点语义统计与校准；支持不足时回退到旧稀有度。`frequency_diffusion.score` 将稀有度用于图通道权重，从报告 POI 出发传播，同时用背景传播抑制普遍活跃的节点；`prepare_scores` 再乘时间亲近度，并把同一交互通道窗口内的成员分数提升为该窗口的最大值。得到主视图 $p_e\geq0$。历史稀有度 $r_e\geq0$ 和 POI 时间/路径相关性 $t_e\geq0$ 是另外两个候选排序视图。它们是**调查优先分数**，不是校准过的恶意概率。

旧基线 E0 需要保持冻结账本原行序，以逐 ID 核对历史结果。新方法 E2/E3 在 E0 之后按唯一事件 ID 规范化事件数组，再重新计算评分、组与路径，从而固定等时间/等深度平局的处理。小图行重排与平行路径测试通过；冻结五案的完整日志重排实验尚未运行。

### 2.2 无标签计算组与候选排名

计算组由同主机的实际无向端点对组成，本轮配置 `across_relations`，组内事件的**总时间跨度不超过 10 秒**。它不按相邻间隔滚动串成无限长组。组分数取成员最高分；人工攻击阶段、参考关键组和文件名/IP 规则均未参与分组。

候选分别在**事件**和**计算组**表示上排序。单视图按 $p_e$ 或组最大 $p_e$ 排序；多视图采用 RRF：

$$
\mathrm{RRF}(x)=\sum_{v\in\{p,r,t\}}\frac{1}{60+\operatorname{rank}_{v}(x)}.
$$

平分由冻结事件 ID 的哈希次序确定。代码也实现了确定性轮询，但 120 项核心实验只运行单主视图与 RRF。`c=60` 是初始设定，不是经过跨案优化的最优值。

组策略先访问组描述符，再按成员主分数降序逐一尝试生成证书。**组引用只是访问顺序，组内成员没有免费入池**。代表成员、继续增加成员、完整组尚未实现为三种独立动作。每池最多扫描 327,680 个成员，实际物化的不同账本事件（含路径连接事件和强制 POI）最多为 32,768 个。诊断分别记录描述符数、潜在成员数、可执行锚点数、证书数和真实物化并集；潜在成员覆盖不能冒充实际候选召回。

### 2.3 合法时间证书与备选路径

一个动作 $a=(\text{anchor},\text{group},W,\text{score})$ 包含锚点及其证书事件集合 $W$。第一份证书保留冻结 `rasp.py` 的 fork 路径：由锚点到共同 pivot 的一支、由 pivot 到 POI 的一支，分别满足有向连接和严格时间顺序。POI 按旧路径规则可暴露其两个端点状态。备选证书从同一时间路径状态搜索得到，去重且逐条验证，最多三份；这里的 $k=3$ **不声称全局三条最短路径**。

对当前已选 $S$，增加证书 $W$ 的真实成本是 $\lvert W\setminus S\rvert$。即使证书静态长度较长，共享已付费连接事件后，它的增量成本也可能较低。若强制集合已超过预算，状态应为 `infeasible_mandatory_budget` 且指标为 null；不得填零分。

### 2.4 三个同池目标与选择

E3 冻结实际可执行动作池后，分别用以下目标选取证书：

1. `edge_score`：$\sum_{e\in S}p_e$。连接事件也计分。
2. `anchor_score`：$\sum_{a\in A}p_a$。连接事件只付成本，不自动算成调查结论。
3. `witness_plus_detail`：对自动计算组的完整路径支持 $C(S)$ 和锚点细节 $D(A)$ 求和，`eta=1`：

$$
\begin{aligned}
\mathrm{complete}(g,S)&=\mathbf 1[\exists a\in g:\ W(a)\subseteq S],\\
w_g&=\max_{a\in g}p_a,\\
C(S)&=\frac{\sum_g w_g\,\mathrm{complete}(g,S)}{\sum_g w_g},\\
D(A)&=\frac{\sum_{a\in A}p_a}{\sum_{a\in\text{pool}}p_a},\\
J(S,A)&=C(S)+D(A).
\end{aligned}
$$

分母为零时相应项取零。同一证书里的必要事件是 AND；可接受的完整证书之间是 OR。这里的“完整”仅指**算法自动组的一份时间路径已齐**，不等于人工标注的完整攻击阶段。

选择器每步检查预算内的可行动作，按启发式增益与新增原始事件成本之比排序；正收益且零新增成本的动作应用一次，不能反复领取收益。`witness_plus_detail` 的排序只计算动作自身所属组的直接收益，而事后 `objective_value` 会计入它顺带完成的其他组。因此本轮评测的是**该启发式实现**，不是 $J$ 的精确边际贪心、全局最优或具有已证明近似比的算法。所选锚点、证书 ID 和事件并集均单独保存。

### 2.5 算法伪代码

```text
输入：冻结账本 E、报告 POI M、历史缓存 H、预算 B
核对输入/历史/配置/源码哈希，拒绝重复事件 ID
在原行序重跑 E0 旧基线，核对每个选中 ID 集
按事件 ID 规范化 E2/E3 的事件数组与历史稀有度
计算频率—扩散主评分 p、稀有度视图 r、时间/路径视图 t
构造最长总跨度 10 秒的无标签计算组
对事件或组按主视图/RRF 排序
逐成员生成合法时间证书；仅在真实物化并集不超过 32768 时入池
对 E2 四个固定池，分别以 B=256/1024 运行 edge_score
从组 RRF 池固定前 8192 个可执行锚点，形成 E3 k=1 和 k=3 两池
每个 k 池复用到三种目标和两个预算；按真实事件并集成本选择
原子写入池、选择、证书、源码/配置/输入哈希，再由独立评测读取标签
```

## 3. 实验如何执行

| 阶段 | 固定对比 | 运行项数 | 问题 |
|---|---|---:|---|
| P0/E0 | v4 `witness_rerank`、v6 `history_channel_portfolio` × 5 案 × B=256/1024 | 20 | 冻结输入、源码及逐 ID 回归是否一致？ |
| P1/E2 | 事件/计算组 × 主视图/RRF × 5 案 × B=256/1024 | 40 | 相同真实物化上限下，表示或融合是否改善检索与选择？ |
| P2/E3 | k=1/3 × 三个目标 × 5 案 × B=256/1024 | 60 | 固定锚点池内，备选路径与证据目标是否有独立收益？ |

共 **120 项实际决策**，不是 120 个独立攻击样本。每案一个进程完成 24 项，缓存的历史、评分与路径在该进程内按协议复用。E2 的四个池分别冻结并跨预算复用；E3 对每个 $k$ 固定自己的池哈希，再比较三目标与两预算。`k=1` 与 `k=3` 的证书池不同，不能称为完全相同的动作池。只比较同一 $k$ 下目标时才是严格同池。

运行顺序是：只读输入审计 → E0 逐 ID 回归 → E2/E3 无标签决策 → 原子保存证书与哈希 → 独立评测 → 事后损失分解与标签 oracle → 报告。`input_audit.json` 记录 Python/依赖、五案账本/历史/POI/报告、哈希及来源；`source_manifest.json` 记录决策源码和评测源码哈希；`experiment_registry.json` 登记每项运行及未执行阶段。重新运行默认拒绝覆盖原输出。

本轮提交前的全量测试为 **681 passed**。其中的小图测试核对证书共享成本、AND/OR 完整支持、时间和主机隔离、强制集合、零新增成本、有限池 oracle 约束，以及行序规范化后的平行路径与候选选择。随机小图只检验实现正确性，不算独立攻击样本。

评测检查：`|S|<=B`、强制 POI、唯一 ID、CDM/合成计数、被选证书事件与 $S$ 的精确并集、每条证书的方向和严格时间合法性。E0 旧基线没有逐动作证书，故其 `time_path_validity` 与候选证书闭包为 null，不能用结构可达比例代替。

诊断把每条已知正例分入互斥的首个未命中阶段：账本缺失、当前时间规则不可达、未实际物化、单份证书加 POI 就超预算、未归因、最终选中。`not_attributed` 不能仅凭贪心选择断言为“预算竞争”。另用标签**仅作诊断**建立有限池 MILP：事件与动作都是二元变量，选证书必须选齐其事件，非强制事件须有证书支持，同一锚点最多选一份，且 $\sum_e x_e\leq B$；目标最大化池内已知正例数。求解器证明最优时才称“有限池上界”。它不是全图上界，也不是部署方法。

## 4. 指标与实际结果

主指标 $R_{\rm known}=|S\cap L|/|L|$，先按案例计算再宏平均。另记录 `group_any`（参考组至少一条）、`group_full`（参考组列出的正例全部出现）、强制 POI 以外的增量召回、所用账本/CDM/合成事件数、预算利用率、结构和执行时间。`precision_proxy`、`f1_proxy` 始终带代理含义；官方等价的 FP、FN、Precision、Recall、F1 为 `NA/null`，因为本地参照没有逐事件完整真值。独立调查命题证据参照尚不存在，`witness_complete=null`。

| 方法 | B=256：已知 TP 合计 / 宏召回 | B=1024：已知 TP 合计 / 宏召回 |
|---|---:|---:|
| v6 强基线 `history_channel_portfolio` | 202 / 60.71% | **321 / 76.96%** |
| E2 四格（各格 TP 相同） | 295 / 61.27% | 298 / 64.58% |
| E3 k=3 `edge_score` | 295 / 61.27% | 300 / 64.75% |
| E3 k=3 `witness_plus_detail` | **54 / 24.66%** | 301 / 65.40% |

E2 在 256 预算的合计增益主要来自 THEIA3，其他多个案例退化；1024 预算明显低于 v6 强基线。THEIA1 的组 RRF 虽访问到潜在包含 239 条已知正例的 8 个计算组，实际物化证书并集只覆盖 **14/239**，最终也只选中 14 条。FD1 的 E2 池实际包含 38/38 条已知正例，但只选中 18 条；剩余 20 条保持 `not_attributed`。证据目标在 256 预算下出现严重回退，不能用较高层“行为覆盖”掩盖原始事件损失。

E3 的 20 个有限池标签 oracle（两个 $k$ × 五案 × 两预算）均证明最优；逐案上界为 18 / 13 / 14 / 229 / 29 条，两个预算相同。这个上界仅对冻结的 E3 池有效。五案单进程总用时约 71.70、60.60、112.86、123.61、32.92 秒；这些是一轮描述性测量，历史缓存已存在，未做五次独立进程性能统计。完整逐案 TP、组指标、损失阶段、oracle 与资源数值分别见 `results.csv`、`candidate_stage_audit.csv`、`oracle_bounds.csv`、`profiles.csv`。
