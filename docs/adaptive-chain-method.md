# 融合上下文稀有度、扩散与整链见证的自适应剪枝

最终对照数值与分阶段损失见 [324 点实验报告](adaptive-chain-results.md)。

本次工作保留原依赖候选抽取及 RASP 对照，新增独立历史模型、整链扩展与预算回退、分阶段损失评估和交互式实验页。该方法用于告警/关键事件驱动的事后调查，不把相关性分数称为攻击概率。文献依据见 [论文笔记](adaptive-chain-literature.md)，历史模型细节见 [上下文稀有度](contextual-rarity-notes.md)。

## 1. 分开定位候选损失和剪枝损失

实验沿用已有的人工选定 POI，其中包含从参考报告得到的调查起点；评估以已知起点为条件，不是自动告警检测率，也不代表未知攻击发现能力。

固定参考事件和路径仅供离线评估，不能进入评分、扩散种子之外的在线参数、候选补边或预算决策。所有方法先冻结选边，再读取正例文件或外部完整链合同。

评估阶段依次为 `source → candidate → temporal_eligible → bundle_eligible → retained`。每阶段同时给出完整参考链数和参考事件数、端到端分母及上一阶段条件分母，按首次丢失互斥归因。集合不嵌套直接报错，零分母返回 `null`。这样可以区分原始日志没有记录、候选没有覆盖、缺少告警相关时序见证和最后预算选择遗漏。扩展触及候选边界仍显示 `candidate_boundary_unverified`。

新漏斗不把“在标注边子图不可达”解释为“在原图不可达”，也不把有资源限制的搜索当成穷尽证明。源参考事件通过数据库事件索引查询；CAPTAIN 大写 ID 的哈希后缀兼容数据库原小写表示。现有候选构造与旧实验接口保持不变。

## 2. 稀有度不再独自代表异常

保留旧边稀有度 `R`。历史模型另外输出精确资源新颖性、同程序/同主机行为模式的平滑惊异度 `S` 和历史支持置信度 `C`。程序从未出现时 `C=0`，不自动将其判为高异常；用户目录、临时随机资源和临时端口只做保守泛化，执行文件名、目标地址等差异保留。

```text
C = N / (N + 20)                 # 跨主机同程序回退再乘 0.75
A = C × S                       # 证据排序分，不是恶意概率
R_context = 0.25 × R + 0.75 × A
```

`R_context` 进入与原 RASP 相同的去重交互图、告警个性化扩散和背景对比扩散；传播边权保留原非零下限，防止高频必要桥边直接失去传播通道。原 `R`、新颖性、上下文惊异度与置信度分别展示，不能把新颖性偷偷重命名为异常概率。

历史来自已建立的 `freq_event_daily`，只统计 **POI 所在 UTC 日之前的完整日期**，严格早于锚点但不包含锚点当天较早事件。按候选主机和程序语义过滤历史以控制内存；未匹配程序/其它路径的同行行为可能未覆盖，来源报告明确记录。每个聚合权重是实际事件次数，先过滤日期再聚合，绝不将候选窗口作为正常历史训练。

## 3. 整链扩展与可行性回退

原方法保留到告警端点的时间见证，不能因此断言已找到入口到最终后果。新模块在候选图内从前后两个方向寻找证据加权的完整观测延续，以每个事件为时态，严格按时间批次发布动态规划状态。同时间戳不能互相馈送；CDM `EVENT_EXECUTE` 使用文件到进程的信息流方向。

完整观测组包含每条必需见证的所有原始边。遇到共享告警端点时拆成真实分支或汇合，不能伪造一条跳转的有向路径。前后延续使用折扣累计证据；默认最多 64 步、4096 个完成尝试锚点，资源截断被记录为不完整。

选择时先尝试整组纳入，所有连接边均计原始事件成本。如果扩展受限或组放不进预算，则保留原时序分叉见证作为回退。锚点采样限制只限制完成尝试，不剥夺旧候选覆盖。预算不足不会偷偷加边；POI 最低成本都无法容纳时直接拒绝该预算。回退见证数量与完整观测组数量分开，二者都不直接成为完整真实攻击链数。

首轮开发实测发现“直接丢弃所有截断组”会严重损失长运行进程的既有覆盖；因此加入了上述回退，并用截断、低分桥、共享端点、预算不足和输入顺序测试约束。这是开发集上的工程修正，不是未见测试集上的盲测结论。

## 4. 完整攻击链的判定合同

`tc_pruning.chain_evaluation.evaluate_chains()` 接受独立参考清单。一个参考可有主 `event_ids`、多个 `branches` 和额外 `required_event_ids`；所有必需原始事件必须留下，每个有向见证必须严格递增且连续，任一分支缺失即整链失败。保留另一条可达路径不能替代参考链的必需步骤。

只有同时满足以下条件的参考进入“已核验完整攻击链”指标：`provenance.kind=independent_review`、`scope_complete=true`、非空 `reviewed_by`、非空 `scope`。这表示外部提供了审核声明，并不表示程序自动证明声明真实。缺源或非法路径不从分母里消失，不进入成功分子。

当前 CADETS 正例来源没有独立完整攻击链清单。因此程序从完整正例事件子图自动派生固定有向时间路径，明确标记 `derived_reference`；它们可以重叠并共享长前缀，不是独立攻击次数，也不是完整攻击活动。合成多阶段、多分支案例有生成器提供的完整真值，单独展示，不与真实数据混算。

无法从缺失或未观测的日志推断出绝对完整性。系统现在能精确回答“给定范围内规定的每条链是否一边不缺，缺在哪一步”，也会如实显示还缺什么证据。

## 5. 实验与网页

```bash
python -m scripts.prepare_chain_references
python -m scripts.run_adaptive_chains \
  --output output/adaptive-chain-study-new-run --publish
python -m scripts.run_adaptive_chains \
  --output output/adaptive-chain-synthetic --synthetic-only
python -m scripts.run_adaptive_chains \
  --output output/adaptive-chain-study-new-run/cadets06 --validate
python webapp/backend/app.py
```

输出目录必须是新目录，避免覆盖冻结证据。真实数据默认读取本次独立的 `configs/adaptive_chain_study.json`；原始数据库和候选账本仍需本机准备，不能靠克隆源码获得原始数据。真实事件参考文件也只在本机保留，先按[参考准备说明](../configs/chain_references/README.md)从已有 CAPTAIN 标注生成。合成实验不依赖这些本地文件。

浏览器访问 `/assets/chain-study.html`；原研究页和本地工作台均有入口。选择案例、方法和预算即可查看曲线、整链数量、断点和原始事件；纳秒时间始终以字符串显示。详细网页报告、CSV、PDF/PNG/SVG 主图由同一次运行生成。公开仓库只包含无逐事件内容的聚合报告；详细报告缺失时网页自动回退汇总，保留主图和阶段计数，并明确提示事件明细未发布。

对照包含原始稀有度评分、仅扩散评分、原 RASP、上下文修正评分、整链选择消融及完整融合方法。所有方法使用同一候选、告警、历史截止和原始事件预算。横轴为实际 `1-kept/candidate`，预算只是上限；纵轴为固定完整参考链分母。阶段曲线应结合候选覆盖上限解读，不能以候选缩小造成的数据消失冒充剪枝压缩。

真实链审核指标无分母时显示 N/A。生成器合成结果只验证构造场景中的机制，三个真实开发案例不足以宣称泛化优势。当前默认线上调查算法保留；新方法和指标通过实验入口提供完整可复核结果。
