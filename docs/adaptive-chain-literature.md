# 自适应剪枝：论文依据与完整链评价边界

本记录依据用户提供的五篇本地论文，以及项目现有 `EVALUATION_PROTOCOL_V2.md`、`rasp-method.md`、`selected-default.md` 和 `uploaded-groundtruth-audit.md`。页码均为 PDF 页码。下面明确区分论文原有方法与本项目的设计推论；不把引用论文的性能移植为本项目实验成绩。

## 一、频次稀有不等于行为异常

### 论文依据

| 本地论文文件（位于 `/root/wenzhang/`） | 页码 | 可核对的原文要点 |
| --- | --- | --- |
| `Hassan 等 - 2019 - NoDoze Combatting Threat Alert Fatigue with Automated Provenance Triage.pdf` | 6–7，§VI | 高频解压事件也可能参与攻击；应考虑其后续行为链。事件概率使用源实体、关系条件下的目标频次，路径组合传播异常信号。进程历史稳定窗口用于修正，路径长度也需要归一化。 |
| `Li 等 - 2024 - NODLINK An Online System for Fine-Grained APT Attack Detection and Investigation.pdf` | 6–7，§V-B | 联合命令行、文件、网络特征。浏览器等高变化进程频繁访问新文件或 IP，直接使用重构误差会产生误报。其 `AS(p)=log(RE(p)/SV(p))` 使用历史同名进程嵌入的簇数 `SV` 修正。 |
| `An 等 - 2026 - CSCProv causal-semantic consistent provenance graph compression for attack detection.pdf` | 9–11，23 | 联合局部结构与行为语义约束节点合并。单一结构或语义相似性可能抹除攻击区别；短而模板化的事件文本仍限制语义表示效果。 |

NoDoze 原文中的 IN/OUT 稳定性不能直接等同于 NODLINK 的行为簇数。NODLINK 的 VAE、FastText、DBSCAN 是该论文的方法，本项目若只复用“历史行为变化应修正异常度”的思想，不能称为复现 NODLINK。

### 本项目设计推论

保留节点类型、关系、行为模式频次形成的原始 `rarity`，同时增加独立的上下文异常证据和历史支持度。原始稀有度表达“少见”；上下文分数表达“偏离当前角色的常见行为”；扩散分数表达“与调查锚点存在结构关联”。这些量都不是已经校准的恶意概率。

一个可实现的条件频次方案是对进程语义类别、关系和目标类别建模，在历史稀疏时回退到类型级统计：

```text
p(event | context) = (n + alpha * p_backoff) / (N + alpha)
history_reliability = N / (N + k)
```

这里 `n`、`N` 必须来自口径一致的历史事件计数，不能将不同独立活跃日比率相加当作概率分布。上述平滑与可靠度公式是项目设计候选，并非五篇论文的共同公式，也不意味着最终实现必然采用此具体参数化。

可将支持度、来源行为变化、严格有序的多事件组合用于调整稀有度；没有历史应显示“未知或支持不足”，而不是直接等同于高异常。校准和频次窗口应严格早于当前调查。高频事件仍可能是必要因果桥，必须允许扩散与完整见证保留此类事件。不能仅为提高标签召回而反向读取攻击参考调分。

## 二、完整路径与完整攻击范围是不同命题

### 论文依据

- **CSCProv，上表所列文件，PDF 15–17 页**：其 Attack Path Completeness（APC）使用从原图攻击标注提取的固定参考路径；同时检查压缩映射后的可追踪性和关键攻击步骤的可区分性。主要面向节点合并，不能简化为“保留了任意一条可达路径”。纯事件删除可采用更直接的原始事件逐项保留检查。
- **`Goyal 等 - 2024 - R-CAID Embedding Root Cause Analysis within Provenance-based Intrusion Detection.pdf`，PDF 7 页 §5.3**：指出数据集标签粒度不统一。其标注流程从入口进行时序搜索，并明确承认会过近似真实攻击图，另由三名研究者独立核对。该流程不是“所有可达节点均为已证实恶意”的证据。PDF 14 页也讨论时间戳与边属性缺失的限制。
- **`Xu 等 - 2022 - DEPCOMM Graph Summarization on System Audit Logs for Attack Investigation.pdf`，PDF 10–11 页**：构建调查图和人工社区划分，再由独立专家复核。其社区真值不能直接当作完整攻击路径真值。
- **NoDoze，PDF 13 页**：依赖上游告警，未被上游发现的攻击不会自动由它覆盖。这支持明确区分告警/候选覆盖与后续图剪枝损失。

### 本项目评价定义

冻结参考清单后再比较预算结果。清单应记录：场景、时窗、入口/终点范围、原始事件 ID、有向时间约束、必需阶段和分支、来源与版本、审核状态、参考范围是否完整。固定参考链的保留要求其全部必需原始事件仍在输出中，而且满足参考规定的方向和时间顺序。另一条连通路径不代替原始参考事件。

分叉攻击应声明多个必需分支。一个分支保留下来，只能说明该分支完整；不能证明整个攻击活动完整。不同分支之间不能为使图连通而虚构边。

指标必须分别表示：

1. 候选图完整覆盖的参考链数量 / 固定参考链总数；
2. 最终完整保留的参考链数量 / 固定参考链总数；
3. 最终完整保留的参考链数量 / 候选完整覆盖的参考链数量；
4. 独立核验且具有完整范围声明的攻击链保留情况。

自动派生路径只能进入派生参考路径指标。合成链作为独立合成验证展示，不能混入真实攻击成绩。没有独立完整链真值时，第 4 项为 **N/A**，不是 0%，也不能用在线选中的路径数量替代其分母。项目现有短参考链的 3/3 或 8/8 不应改称完整攻击活动数。

**从已观测日志中保证某个事件序列没有缺边，无法证明未观测的全局攻击链完整。** 采集遗漏、窗口之前的入口、窗口之后的后果、未覆盖主机和未标注分支，都可能使观察范围不完整。自动延长调查路径能缓解遗漏，但不能消除此信息边界。界面应显示范围、缺失阶段与截断状态。

## 三、保留候选抽取，增加分阶段损失归因

分阶段诊断是本项目提出的工程审计方法，不冒称某篇论文的完整原算法。

```text
固定参考
  → 源日志可见
  → 调查范围 / 源图时序可达
  → 候选覆盖
  → 完整时间见证
  → 预算可行
  → 最终保留
```

每个阶段同时统计事件数与完整链数；整链成功要求全部必需事件及分支成功。将各链/事件归入其最早失败阶段，避免多次计数；源记录缺失、候选搜索遗漏、结构见证缺失和剪枝损失分别呈现。零分母返回空值与原因。

现有 `tc_pruning/search_diagnostics.py` 可提供参考，但有两项需要特别说明：

- 只在标注边子图上搜索“因果范围”会遗漏经过未标注桥边的真实依赖，因此不能据此证明目标在源图中不可达。
- 带资源和超时上限的诊断搜索，即使名为 `exhaustive`，也不能自动作为绝对穷尽上界。应保留 `unknown` / `truncated` 状态。

若阶段集合并非包含关系，应报告偏差并按互斥规则归因，不能把各集合之差直接累加为损失。参考标签只能用于结果审计，不能作为在线候选扩张或保留预算的隐式输入。

## 四、主图及网页展示口径

主图标题为“压缩率—完整参考链保留率”。横轴使用实际值：

```text
actual_compression = 1 - retained_original_events / candidate_original_events
```

配置预算只是上限，不能替代实际压缩率；候选抽取缩小源数据范围也不能算成剪枝压缩。纵轴使用固定参考分母，候选完整覆盖率作为独立上限线。真实与合成案例分开选择，保留原方法、稀有度、扩散及融合对照，且使用相同候选图和原始事件预算。

网页同步提供完整/断裂链列表、必需事件的原始 ID、方向、原始时间字符串、缺边及最早损失阶段。纳秒时间戳应按字符串传输和显示，避免 JavaScript 浮点整数精度损失。指标旁保留独立的“已核验完整攻击链”项，没有真值则显示 N/A。

事件卡片按信息流因果方向展示；对于 `EVENT_EXECUTE`，可执行文件影响进程，即原始记录的目标指向源，并额外注明原始系统调用方向。可选评分证据以折叠表区分原始稀有度、新颖度、上下文偏离、历史置信度、上下文异常分和融合分；缺失证据不填造数值。

这一展示能够回答“当前固定参考里究竟保住了多少条整链、在哪里断了”，不能独自回答“现实世界全部攻击链是否均已发现”。
