# 历史回查：先补候选覆盖，再检验选边召回

## 论文依据和实际改动

[LEONARD / The Case for Learned Provenance Graph Storage Systems，USENIX Security 2023](https://www.usenix.org/conference/usenixsecurity23/presentation/ding-hailun-provenance)
研究溯源图存储和查询，说明调查候选图与底层证据存储应分别考虑。本轮没有复现它的神经存储模型，也不使用它的性能数字作为本项目结果。
[AIQL，USENIX ATC 2018](https://arxiv.org/abs/1806.02290) 利用系统事件关系和时间条件进行调查查询。本轮借鉴实体/时间过滤，采用确定性的端点分片索引，不是 AIQL 查询优化器复现。

实现 `HistoryArchive`：逐批追加规范化事件到 gzip 分片，每片记录端点集合、时间范围和 SHA256，原子发布 manifest；可重开查询，无需预置 SQLite。
已观察告警的端点登记表不会随热窗口清除。查询两跳相关历史，与热窗口取并集，然后重新传播和剪枝。检索不读取攻击标签，严格排除查询截止时间之后的事件。
检索是无向端点邻域，不是已证明的攻击路径；之后仍需有向严格时序分叉选边。所有恢复边与连接都计入同一个绝对边预算。
若不扩大候选图，已滑出窗口的事件不可能由更好的打分重新创造出来。

## 三天固定 4000 边上限对照

使用相同批量 RASP 评分配置、既有 POI、历史频次账本；所有掩码冻结后读真值。主检索范围事先设为两跳，一跳为检索消融，全历史为参照。时间为流结束时刻，不能称为逐时刻在线检测效果。

|案例|全部攻击事件|仅窗口最终召回|两跳检索候选覆盖|两跳最终召回|全历史最终召回|
|---|---:|---:|---:|---:|---:|
|CADETS-06|268|30.60%|100%|100%|100%|
|CADETS-12|5000|0%*|99.40%|15.34%|15.34%|
|CADETS-13|498|16.67%|83.33%|76.51%|81.93%|

*CADETS-12 最后窗口内没有 POI，旧窗口方案无法生成有效调查结果；0% 是其未提供任何保留结果的评估，不是“把已评分的攻击全删了”。
所有行分母都是全部标注攻击事件，不采用窗口内分母。CADETS-12 仅 4000 边预算，哪怕完美排序也最多容纳 5000 攻击事件的 80%，实际还需留连接。当前 15.34% 远低于这个上界，排序瓶颈仍然存在。
CADETS-13 仍有 83 条攻击事件未被两跳候选找回，候选内另丢 34 条，分别属于检索和剪枝损失。
CADETS-06 的纯窗口只使用 695/4000 预算；历史检索使用 4000/4000，不能声称其实际存储量相等，只能说预算上限相同。

两跳候选边数：33894 / 46885 / 23539，均小于完整候选图 102232 / 138261 / 35967。
但端点索引粒度是分片，查询两轮累计扫描 159464 / 251522 / 66934 条记录，**不是亚线性查询速度保证**。
真实工程应继续改为倒排偏移或更小块，并评估高频共享实体造成的扩张，而不是隐去查询成本。

## 接入微批流水线

实际微批成对验证（CADETS-13，2026-09-10_18-36-17）：两方法都每批 5000 条、使用动态传播和到达历史频次、最终上限 4000 边。仅窗口保留 83/498 攻击事件（16.67%），开启历史回查保留 377/498（75.70%）；参考短链从 2/3 到 3/3。恢复后候选 23539 条。该结果与上表批量评分器的 381/498 不同，不能混用；目前只验证这个开发案例，未做告警延迟全曲线。

`run_stream_rasp.py` 新增 `--history`，与动态 PPR 和原有窗口剪枝结合。原始日志和分片不删除；恢复窗口外候选不会增加原窗口计算出的最终保留边上限。
另外修正了流式时序选边中 `EVENT_EXECUTE` 的信息流方向，使其与批量 RASP 一致（文件到进程）。
这是检索与评分原型：读取 manifest 可恢复查询，但完整读取偏移、告警表、频次和 PPR 检查点尚未持久化；不支持安全地自动续跑写入或多写者。
分片保存规范化事件/历史稀有度，原始 CDM 仍是完整证据源；分片加原文件会增加磁盘使用，不应称为物理存储压缩。

```bash
cd /root/NODOZE-pruning-release
run_id=$(date '+%Y-%m-%d_%H-%M-%S')
setsid -f python -u -m scripts.run_stream_rasp \
  --input output/tc/cadets13-chronological-replay.jsonl.gz \
  --poi configs/stream_cadets13_pois.json --history \
  --batch 5000 --window 20000 \
  --output "output/tc/stream-history-${run_id}" \
  > "logs/stream-history-${run_id}.log" 2>&1 < /dev/null
```

示例输入是离线排序后的 CADETS-13 回放文件；可改为原始 CDM JSONL，但必须使用对应告警 ID。
三天的独立候选检索实验可运行 `python -m scripts.run_history_recall --ledger ... --reference ... --output ...`，本轮输出前缀为 `output/tc/history-recall-CADETS-XX-2026-09-10_18-35-08`。
本轮结论是显著修复历史候选缺失，而非全面超越离线 RASP，更没有证明未知攻击上的泛化。
