# 节点驱动调查产品计划

## 交付定位
面向企业 SOC / 事件响应团队的单组织私有部署试点版本。用户从进程、文件或网络节点开始，明确选择时间锚事件，设置原始事件预算；频率统计和节点个性化扩散排序，完整时序路径参与预算。无外部告警依赖。默认仅剪枝，不推断恶意、不读真值、不承诺检测召回。

## 当前问题与设计决策
1. 共享缓存被每次重算覆盖 → 每次调查独立持久化，冻结参数、数据摘要与证据；旧研究接口也停止覆盖源数据。
2. 输入实际上只有事件 ID → 一等节点搜索，节点关联事件选择，节点单点 PPR；锚事件明确约束时间，完整路径仍到锚事件。
3. “减少阅读量”与攻击推断混淆 → 显示事件缩减比例、预算使用、路径证书；研究检测器留在 /research。
4. 全图网状渲染不利调查 → 起点居中、双图同布局、有向局部预览、明确预览数量和全量指标，完整证据可导出。
5. 缺少稳定交付边界 → 可配置单组织口令会话、同源写入保护、持久运行记录、结构化错误、私有部署说明。默认仅回环地址演示。
6. 实验强度不足以称全面超过 SPARSE → 真实案例性能与合同校验留存，缺少完整真值时检测指标仍 NA。

## 任务
### 1. 算法合同
测试后实现节点单点个性化 PPR、纯剪枝路径，保留现有默认研究兼容性。非法节点/无历史/预算不足明确失败。
### 2. 调查服务
测试后实现节点搜索、时间锚候选、不可变运行、运行证据/JSON/CSV 导出、审计摘要与输入哈希、读写错误边界；源缓存只读。登录可配置，写请求同源。
### 3. 企业工作台
实现节点→锚事件→预算→调查→证据导出；结果重开/历史、同坐标有向局部图、保留原因/完整见证详情、移动屏幕与键盘访问。研究页面保留。
### 4. 验收和交付
真实 10/30/60 分钟 OpTC 案例，至少一次改节点、预算、重开、CSV/JSON下载。全套测试和浏览器验证；给出实现/问题/性能/部署/商业试点验收文档。

## 验收与边界
输入缓存不变；两次调查互不覆盖且重启可重开；所有保留事件满足预算/起点/时间路径/账本复放；报告包含未用预算，不强行凑满。节点焦点改变传播分但不伪造节点专属可达性保证。无多租户/RBAC/SSO/计费，不宣称满足全部企业正式上线要求。试点以明确验收范围销售，正式合同前需数据授权、独立数据和部署环境验收。
