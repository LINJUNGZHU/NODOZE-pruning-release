# NODOZE 节点调查产品：评审与交付

## 1. 导师判断

原系统具备可用的研究核心，但原界面仍是实验展示。客户容易误解“攻击识别”“剪枝缩减”“部分正例找回”是同一个指标；共享案例会被重算覆盖，节点不能直接作为扩散焦点，数据准备绑定公开案例。这样的状态不适合交付调查服务。

本轮已实现**单组织私有部署试点**：从指定进程、文件或网络实体出发，以关联事件约束时间，在原始事件预算内输出带完整见证的调查子图。节点真正决定 PPR 单点传播起点。频率统计、背景对比和图传播仍是自有算法中心；新增的是节点输入、纯剪枝合同与稳定的产品工作流。

可以按这个明确范围销售付费试点。当前还不能对外承诺完整企业平台、自动检出未知攻击或全面超过 SPARSE。

## 2. 当前问题、修复与剩余边界

| 问题 | 本轮处理 | 当前边界 |
|---|---|---|
| 结果覆盖原案例，调查间相互影响 | 每次生成独立运行 ID，SQLite 原子保存压缩证据，源缓存只读 | 同一组织内共享调查记录；没有多租户 |
| 输入仅是事件 ID，节点定位没有体现在算法中 | 节点搜索 → 选择关联时间锚 → 单节点个性化 PPR | 时间见证仍以锚事件两端展开，不能声称全体保留事件都存在从焦点出发的单向路径 |
| 攻击检测与剪枝指标混杂 | 产品默认纯剪枝，不运行检测器、不读取参考真值、不接外部告警；研究页面 /research | 未确认事件不会被标记为“安全” |
| “减少阅读量”营销口径无人工实验支持 | 改为准确事件缩减比例、实际保留量、预算使用、未用预算和路径核验 | 人工调查节省多少时间尚未实测 |
| 大图杂乱，视觉缩减容易误导 | 同一节点邻域、同一坐标、有向事件预览；独立哈希选显示事件；显示局部/全量分母 | 最多预览 180 条直接关联事件；多跳见证在详情/导出核验 |
| 缺少稳定审计与复核 | 导出完整保留事件、原始日志、候选决策输入、哈希、账本、证书；已有离线验证器可复放 | 哈希不是数字签名；当前不提供不可抵赖性承诺 |
| 研究运行挤掉产品历史记录 | SQL 先过滤产品运行，再分页；显示总数 | 历史保留、备份与清理由部署方管理 |
| 原数据源离线后无法重开 | 冻结结果先展示，源数据准备是可选步骤；离线可查事件与导出 | 重新运行需要恢复候选与历史索引 |
| 客户只能使用固定公开案例 | 新 prepare_customer.py；无需真值与 POI，显式主机和时间窗口 | 当前支持 eCAR 格式 JSONL / JSONL.gz 的 FILE、PROCESS、FLOW；其他格式需适配 |
| 演示服务器直接用于交付 | Gunicorn 启动配置、回环绑定、可选共享口令会话、同源写入保护、结构化错误 | 口令模式是单组织访问控制；无 RBAC/SSO |

## 3. 核心算法

### 输入

只读 schema v2 事件账本与同主机历史 SQLite 索引；节点 v；直接关联锚事件 e₀；原始事件预算 B。候选窗口由操作员显式提供，不由真值裁剪。拒绝无历史、索引不匹配、重复事件 ID、非关联锚和不合法预算。

### 频率统计

严格使用 t < t(e₀) 的历史，不包含同刻或之后事件。

- 语义签名保留交互类型与语义实体信息；网络签名不把临时客户端端口当成行为。
- c(e) 为历史同签名次数，稀有度 r(e) = 1 / (1 + c(e))。
- 对重复端点/关系合并传播通道，保留原始事件成本和身份。

### 节点个性化扩散

令 sᵥ 为只在用户所选节点上取值 1 的向量：

`pᵥ = α sᵥ + (1 − α) Pᵀ pᵥ`

背景 PPR 以进程节点为分布。端点相对背景的增益与稀有度融合得到调查相关性。迭代残差 / α 提供数值误差上界；支持证据的增益须越过误差界。没有把扩散分数解释成恶意概率。

与旧事件起点的区别：旧方法把起点质量各一半放到锚事件两端；产品模式把全部起点质量放到所选节点。并未引入 GNN，也没有替换成 SPARSE。

### 完整时间见证与预算

按时间构造严格递增的有向链接；同刻事件不互相供给。锚事件暴露两端状态，可形成回溯与分支见证。按完整路径新增收益 / 新增事件成本选择，路径连接边计入 B，共享边只计一次。预算是上限，证据不足时不会填满。

保存前检查：预算有效、锚保留、时间链接合法、见证完整、账本可复放。导出包含输入与原始事件 ID；可执行：

```bash
python webapp/scripts/verify_decision_audit.py downloaded-evidence.json
```

这个复核检查已保存分数下的选边、见证和预算；它不是自动重新验证外部原始日志真实性或重算全部历史统计。

## 4. 实验结果

### 配对算法可行性实验

[原始记录](benchmark.json)；[复现实验脚本](../../scripts/benchmark_product.py)。三个真实 OpTC 窗口，5% 原始事件预算；对比原事件两端起点与节点单点起点，其他剪枝条件相同。锚来自已有演示预设，用于配对复现，不代表自动发现 POI。没有用真值计算检测性能。

| 候选事件 | 预算 B | 原事件起点保留 | 节点起点保留 | 节点事件缩减 | 节点算法用时 | 保留集合 Jaccard |
|---:|---:|---:|---:|---:|---:|---:|
| 27,011 | 1,350 | 498 | 501 | 98.15% | 2.93 s | 0.9940 |
| 86,318 | 4,315 | 917 | 942 | 98.91% | 9.55 s | 0.9735 |
| 188,609 | 9,430 | 1,680 | 1,707 | 99.09% | 19.22 s | 0.9842 |

两种模式每次都通过预算、起点、时间链接、完整见证和账本校验。用时包含内存候选复制与算法，不包含输入文件加载、持久化和浏览器传输；每条件一次运行，不能作为 SLA。进程累计峰值 RSS 约 2.50 GiB，不是单方法独立内存测量。当前代码仍会完整加载并复制候选，因此不能承诺海量日志在线服务。

**对照结论：** 保留集合高度重合，节点单点输入提供明确的调查焦点和分数变化，但本组结果没有证明它在检测性能上胜过旧算法。也没有作者版 SPARSE 同口径复现，不报告“超过 SPARSE”。

### 网页端到端验收

[浏览器记录](browser-validation.json)。真正通过节点搜索和关联事件选择发起调查；27,011 条候选，在 B=1,000 下保留 502 条，事件缩减 98.14%，未用预算 498。端到端时间以记录中的 full_ui_seconds 为准，与上表锚和测量范围不同。

已验证：第二次 B=256 调查不覆盖第一次，JSON/CSV 下载，原始日志与见证详情，历史重开，390 px 屏幕无横向溢出，原数据接口离线时仍可重开和下载。没有浏览器 JavaScript 异常。

FP、FN、Precision、Recall、F1 全为 `NA`。部分工件/实体标注可以作研究正例核验，不能把未标注事件当正常，也不能靠论文表格倒推出当前逐事件真值。

## 5. 商业卖点如何表述

**建议一句话：** “围绕你指定的节点，在可控事件预算内收拢带时间路径的调查证据，支持原始事件复核与导出。”

可展示：无需外部告警、节点是真实传播起点、保留路径计入事件预算、原始数据只读、结果可重开、决策可离线复放。展示减量时同时展示保留数和证据约束，不只展示百分比。

不应写：检出率 100%、零误报、比 SPARSE 更准、调查时间减少 98%、支持任意日志或全部企业权限体系。当前没有相应验收证据。

## 6. 销售与下一阶段验收

交付项：软件私有部署、限定格式的数据适配、节点调查操作培训、证据导出与审计说明。以一个组织、一类数据源、明确事件规模和约定调查任务为试点范围。报价取决于数据适配和支持范围；本轮没有捏造市场价格。

下一阶段需要补充：

1. **盲测调查效用：** 新客户数据按主机/时间隔离训练与验证；分析员在全图、频次排序、节点剪枝三个条件下完成同样任务，记录用时与回答正确性。不要重复使用被优化过的公开案例给出泛化结论。
2. **证据与预算曲线：** B=64/256/1,024/5%/20%，记录独立人工确认的关键事件和完整见证保留，不把已知正例之外的事件算 FP。
3. **部署性能：** 隔离进程重复运行至少 5 次，区分冷启动、纯算法、保存、重开、导出；在客户硬件和候选规模下验收 p50/p95、峰值内存与队列冲突行为。
4. **算法剩余风险：** 高频真实攻击可能被背景对比压低；无历史无法打分；候选窗口外事件无法找回；无向扩散排名须靠有向时间见证约束；新关系与跨主机适配仍需验证。
5. **商业交付边界：** 当前仓库未附软件 LICENSE/NOTICE，且含研究资源。正式分发前需由权利方确认代码、第三方依赖和演示数据可交付范围；本轮未重新许可任何研究论文、数据或第三方实现。
