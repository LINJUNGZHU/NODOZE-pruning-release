# CADETS 三日 POI 前缀增量实验设计

## 1. 实验问题

本实验回答：CADETS E3 的 UBC-06、UBC-12、UBC-13 三个攻击日中，按攻击报告时间线逐个增加 POI 时，最少需要多少个 POI，才能在固定 20% 原始事件预算下达到该日可观测到的最大完整攻击路径恢复量。

它不是用 Ground Truth 反向搜索“最优 POI”。POI 的身份与顺序只由 DARPA 报告中描述的攻击阶段及数据库内对应事件确定；Ground Truth 仅在剪枝后度量路径恢复。

## 2. 固定实验变量

每个攻击日分别执行 POI 前缀 `P_1, P_1..P_2, ..., P_1..P_n`。同一攻击日的所有前缀共享：

- 固定调查时间窗；
- 固定、完整的报告对齐参考路径集合；
- 相同 RDP-Guard 配置与 20% 原始事件预算；
- 相同历史频次截止策略和频次快照；
- 相同候选图搜索资源限制。

仅 POI 前缀长度发生变化。这样，相邻点的路径增益可以归因于新增 POI，而不是评测标签、时间窗或预算变化。

## 3. 三日 POI 池

- UBC-06：3 个报告语义 POI，依次覆盖 nginx 外联、载荷早期回连、载荷晚期回连。
- UBC-12：8 个报告阶段 POI，依次覆盖 nginx 连接、XIM 落地/执行/C2、main/test 落地、test 执行/C2。
- UBC-13：3 个报告语义 POI，依次覆盖 nginx 外联、pEja72mA C2、sshd 影响分支 C2。

加载时必须在数据库中解析所有事件并按 `(timestamp_ns, event_id)` 校验严格的确定性时间顺序。缺失事件、重复事件、倒序事件和空池都视为输入错误，不静默跳过。

UBC-13 的固定窗口向后延伸到第三个 sshd POI 的时间戳。该 POI 比 UBC 官方核心实体窗口末端晚约 27 秒，但 DARPA 报告明确描述该 sshd C2；输出元数据必须标记这一窗口扩展，不能把它伪装成官方核心窗口。

## 4. 固定参考攻击路径

每个攻击日从已有 UBC 人工审查恶意实体清单及其时间窗内内部事件出发，构建一份固定参考清单。对完整 POI 池中的每个终端 POI：

1. 以终端事件在信息流方向上的因果源端为回溯起点；
2. 在 UBC 核心事件中沿严格时间倒序的前驱边做广度优先搜索；
3. 选择到“此前不再有合法核心入边”的时间展开入口的确定性最短因果链；
4. 将终端 POI 事件追加到路径中并去重；
5. 把完整池的所有路径和 POI 事件合入参考事件集合。

每条路径在写入前必须验证相邻事件的因果端点相接且事件顺序严格递增；仅含终端 POI 的路径必须显式标记为“终端因果源本身即时间展开入口”，不能作为未说明的搜索残片。该路径是“DARPA 报告 POI 锚定、UBC 核心实体约束下的数据库派生路径”，不是人工逐边标注路径。元数据必须披露这一边界。参考清单在该日所有 POI 前缀运行中保持不变。

## 5. 在线与离线隔离

每次前缀运行创建独立的告警清单，只含当前前缀 POI 和固定时间窗。在线候选搜索、历史频率、稀有度、图扩散、RDP-Guard 打分和路径证书只读取这份告警清单。

固定参考攻击清单只作为 `groundtruth_annotations` 在剪枝完成后参与指标计算。它不得改变候选图、打分、阈值、保护边或推荐点。

## 6. 指标

每个前缀记录：

- 候选事件数、候选节点数、保留事件数和实际保留比例；
- 事件压缩率、攻击事件召回率和完整参考路径保留数/率；
- POI 证书、阶段对证书、预算可行性和保留分数质量；
- 运行耗时与新增 POI 带来的完整路径边际增益。

为避免“选中的 POI 路径被硬保护”导致虚高，完整参考路径再分为：

- `selected_terminal_paths`：终端 POI 已在当前前缀中；
- `unselected_terminal_paths`：终端 POI 尚未用作种子。

同时报告两组的保留数/率。后者称为未播种路径恢复率，是衡量扩散能否从少量 POI 恢复更多攻击链的关键指标。若某前缀不存在未播种路径，其比率记为 `null`，不记作 100%。

## 7. 最少充分 POI 判定

对每个攻击日，先取所有合法前缀中完整参考路径保留数的最大值 `M`。最少充分 POI 数 `k*` 是满足以下条件的最小前缀：

- 完整参考路径保留数等于 `M`；
- `path_certificate_valid` 为真；
- `budget_feasible` 为真。

同时报告 `M / total_paths`。如果最大值仍小于全部参考路径，必须明确标记“达到本次曲线最大值”而非“完全恢复”。跨日汇总报告 `sum(k*)`、平均 POI 比例、宏平均完整路径保留率与宏平均未播种路径恢复率。

## 8. 执行与产物

新增单一 CLI 驱动读取实验规格，顺序执行 14 个前缀，避免并行运行放大 SQLite I/O 与内存占用。常规 `experiment` 的方法对比保持默认开启；本扫描显式关闭重复的消融曲线，只运行 RDP-Guard 主方法。

输出目录以日期时间命名，包含：

- 每日前缀告警清单与固定参考清单；
- 每个前缀的完整 JSON 结果；
- `summary.json`、`summary.csv` 和 `summary.md`；
- 可原样复现的输入路径、配置、窗口、POI 顺序及判定规则。

后台 shell 日志也使用同一日期时间。进度文件按当前场景和前缀持续刷新，用户可用 `tail` 查看。

## 9. 验收标准

- 单元测试覆盖 POI 顺序/缺失校验、固定前缀窗口、选中与未选中终端路径指标、最小充分 `k*` 判定以及关闭消融的行为；
- 全量测试通过；
- 三个攻击日共 14 个前缀全部完成，没有结果复用或中途漏项；
- 每个前缀使用同一 20% 原始事件预算并输出有效性证书；
- 最终给出可复现后台命令、日志/结果路径以及每一天的 `k*` 和路径恢复曲线。
