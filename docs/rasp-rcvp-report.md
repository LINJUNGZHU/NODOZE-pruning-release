# RASP-RCVP 实施与评估报告

2026-09-13。算法与网页均在原项目上扩展；新算法保持显式实验选项，旧默认不切换。完整公式、数据流、配置、文件职责与测试索引见 [实现说明](rasp-rcvp-method.md)，论文思想与实现边界见 [研究来源](rasp-rcvp-references.md)。

## 实验口径

本轮仅汇总当前 `benchmark-admission.json` 允许且已完成的 CADETS 06/12/13 三个场景。按用户要求，后续不执行或重跑 THEIA；此前已启动进程保留运行，但不等待、不纳入本轮结论。候选图使用既有冻结 ledger，所有方法共享相同原始事件、POI、历史分量、预算与固定参数，避免候选变化混入剪枝收益。它们已有开发使用历史，不是新的 held-out 测试集。

正式准入仅支持正例实体保留。事件标签由已审核正例实体之间的窗口内交互派生，不是完整人工攻击事件标注。`attack_event_recall` 必须结合该派生标签定义阅读；实体保留不能冒充完整攻击节点分类。没有完整负标签，因此不报告主指标 precision/F1。OPTC 仅用于网页开发诊断，未重新包装成正式完整路径 benchmark。

在线重放先写出全部方法与预算的 mask、逐边通道、根、配置和实现哈希，随后才读取正例实体归档与 reference。GT 不参与评分、根选择、冗余签名或预算决策。原始输入与大型逐边 gzip 留在本机 output，Git 仅提交代码、配置与紧凑报告。

| 方法 | 传播 | 选择器与比较含义 |
|---|---|---|
| A_rasp | 现有 RASP 重新计算 | 现有 select_fork；单独标记网页侧 legacy 对照 |
| A_rdp | 原 ledger 的 legacy diffusion | 相同固定 RDP-Guard 权重重放，重建原 merge 原子组和有序证书输入 |
| B | uniform relation mixing，无 time/fanout/反向通道/核验 | 同 A_rdp 选择器 |
| C | B + time/fanout | 同 A_rdp 选择器 |
| D | C + backward 通道与根定位 | 同 A_rdp 选择器 |
| E | D + root-forward 调和核验 | 同 A_rdp 选择器 |
| F | 与 A_rdp 相同 diffusion 与融合分量 | progressive + 固定 legacy witness 依赖 |
| G | 与 E 相同 diffusion 与融合分量 | progressive + 核验支持与固定 witness 依赖 |
| G_no_redundancy | 与 G 相同 | 仅 redundancy_weight=0，隔离弱冗余正则 |

A_rdp 是 **joint frozen-component replay**，并非重新运行原 PS-RDP 的所有 POI-local 频次与 noisy-OR 累积过程；`source_frozen_final_score` 另存以避免混淆。它作为此消融的受控旧传播输入，不宣称完全重现 README 中历史生产曲线。新 CLI 的实际 POI-local 累积能力另外通过真实双 POI 集成测试验证。当前三场景矩阵不改变 POI prefix，prefix monotonicity/churn 的场景级指标为 N/A。

三类 miss 必须分开：candidate miss 为 reference 中未进入候选的部分；pruning miss 为已进入候选却被删除的部分；end-to-end recall 分母是完整 reference。表格中不得用 conditional retention 代替 end-to-end recall。原始派生路径包含可能同时间戳的序列，另划出满足严格方向与严格递增时间的子集；人工完整攻击路径保留仍为 N/A。

40k profile：五次 `temporal_pass` 累计 1.472 s，`build_operator` 0.147 s；状态发布与 timestamp sweep 占主要成本。排序/去重为 O(E log E)，固定 family 数的传播扫描近似 O(E)，lazy heap 为 O(G log G + dependency updates)，不是每删一边重新全图传播。此前发现的重复整组 tuple 构建、全表迭代依赖闭包与网页逐边 witness 展开已改为共享元组、worklist 和稀疏直接依赖。真实场景又暴露大原子组审计的 eager setdefault 默认值计算；现改为每组仅计算一次优先级，并避免对同组元组逐边重复哈希。2,000-edge 保护组的证据读取次数从约 8,002,000 降为不超过 6,000，操作次数测试防止回归。CADETS 13 优化前后 36 个输出 mask 与整个逐边 gzip SHA 完全相同，online_total 从 204.22 s 降到 67.90 s，G@5% 选择从 13.63 s 降到 2.20 s；均为同机并行实验负载下的记录，不作为隔离微基准。THEIA 原窗口有 566,561 个时间戳，其中 565,617 个恰含两条事件（其它为 singleton 927、三事件 11、四事件 6）。原向量路径在这些微小分组上反复创建数组和排序；该版完整矩阵运行约 39 分钟后因确认该开销而中止，不能当作成功实验结果。新 <=4 事件快速路径严格分离整组读取、退休和发布，保持数值索引 tie-break。2 万 paired 事件对照由 4.36 s 降到 0.407 s、分数逐位相同，新增 2/3/4 事件分组对照测试也核对全部通道、根与父指针。单事件合成图的性能不能代表这种时间戳分布。小分组优化后，三个真实 CADETS 场景的最终决策哈希均相同，但逐边审计并非逐位一致：存在浮点舍入与获胜见证解释差异，不能把合成对照的逐位一致推广到真实场景。最终三个 CADETS 场景均已重新生成；THEIA 不作为本轮交付依赖。极长固定见证、原子组闭包、既有证书规划和大体积 JSON 审计仍可能支配真实场景时间/内存；已完成场景 RSS 与阶段时间须结合结果表阅读。

## 已知局限与负结果边界

- exact max-product 只保留最强支持见证，不对所有路径求和；不能把分数解释为 PPR 概率。
- 原始背景常见的上游边仍可能通过独立 roundtrip 通道得分。核验表示合法一致性，不能证明恶意，也不保证排除所有正常 hub。
- 固定根 quantile/cap 可能丢弃低支持长链根；固定 witness 守卫可能因未搜索替代路径保留冗余或导致预算不可行。
- 冗余只是重复交互签名弱正则，尚未实现完整 semantic/relation redundancy 学习。独立零冗余消融用于检查它实际是否带来收益。
- 可选谱失真、Steiner solver 与独立人工完整路径数据均未引入；不以无向结构指标恢复时序非法边。
- RCVP 网页处理时间高于 legacy；新传播/剪枝成本必须计入结果，不能仅报告事件压缩率。

## 对十个研究问题的回答

1. **relation-aware 改善什么？** 机制上改变关系间质量分配，防止 raw 邻居数量单独支配；B 对 A_rdp 的派生事件保留为 0 胜 / 11 平 / 1 退步（12 个同场景/预算点），这不足以证明全面收益。完整正例实体和路径指标仍需同时阅读。
2. **反向/正向核验排除什么？** toy 验证排除了逆序、同刻伪链与无合法 POI 锚点见证的根，上游 harmonic 不会由单向 max 放大。真实派生事件上 D/C 为 4 胜 / 4 平 / 4 退步，E/D 为 1 胜 / 11 平 / 0 退步。因果一致不等于恶意，不能声称识别了真正攻击源或去掉所有正常 hub。
3. **progressive 收益来自哪里？** 固定传播输入下 F/A_rdp 为 7 胜 / 3 平 / 2 退步，G/E 为 7 胜 / 3 平 / 2 退步。变化来自 raw-cost 组优先级、固定 witness 依赖以及弱 consistency/redundancy 的组合；不是仅凭‘渐进’二字可证明的优势。G 对零冗余 G_no_redundancy 为 0 胜 / 8 平 / 4 退步，因此冗余项也不能预设有益。
4. **只在 20% 有收益吗？** G 对 A_rdp 的派生事件逐预算比较：5%：1 胜 / 1 平 / 1 退步；10%：1 胜 / 1 平 / 1 退步；20%：2 胜 / 0 平 / 1 退步；30%：2 胜 / 0 平 / 1 退步。同时存在实体与路径权衡，不能只引用 20%。
5. **5%/10% 是否退步？** 派生事件退步点为 CADETS 13 5%：G 7 vs A_rdp 8；CADETS 13 10%：G 14 vs A_rdp 22。例如 CADETS 12 在 5% 的正例实体为 G 24/43、A_rdp 41/43；不能把事件数量改善当作所有调查质量都改善。
6. **完整攻击路径严格保留吗？** 独立人工完整攻击路径没有准入标签，仍为 N/A，不能保证全部恢复。G 的严格派生子集未全保留点：CADETS 12 5%=3/8；CADETS 12 10%=3/8。G 声明 strict multistage 证书无效点：CADETS 13@5%；CADETS 13@10%；CADETS 13@20%；CADETS 13@30%；这与 GT 派生路径是不同对象。预算不可行点：无。
7. **candidate miss/pruning miss 各多少？** CADETS 06：candidate miss 237/268；G 在 5/10/20/30% 再删除候选内参考事件 17,17,17,1/31；CADETS 12：candidate miss 4357/5000；G 在 5/10/20/30% 再删除候选内参考事件 625,617,605,604/643；CADETS 13：candidate miss 459/497；G 在 5/10/20/30% 再删除候选内参考事件 31,24,11,11/38。两者分母不同，前者限定候选上限，后者衡量剪枝损失。
8. **额外时间/内存是否明显？** 是。上表列出各场景真实阶段成本；网页并行负载下 full 约 13–14.5 s、legacy 8.1 s。已修复原子审计二次开销和小同刻分组常数开销，但不能用 singleton 合成吞吐率替代 THEIA 实测。A_rdp 的冻结分量成本不等同完整原管线成本。
9. **是否存在 GT leakage？** 在线传播与选择接口不接受标签，runner 在全部 mask 与审计冻结后才打开参考归档。实际 CLI 使用两个不同 GT 文件的测试得到相同在线账本 SHA；代码审查和测试未发现泄漏。三个场景开发使用历史如实披露，不宣称独立盲测。
10. **是否升级默认？** 不升级。跨场景、多预算、事件/实体/路径指标没有稳定一致的优势，且有明显性能成本。保留 opt-in 传播与 progressive 实验分支以及负结果文档，旧 RASP/RDP-Guard 默认不切换。
